## 写测试要注意

Obsidian 端的测试用 `Module._load` 劫持 `require('obsidian')`，跑在一个假的 DOM 上。这个假 DOM 只有这些能力：

- 有：`children` / `textContent` / `classList` / `createDiv` / `createEl` / `querySelector` / `querySelectorAll` / `setText`
- **没有**：`style` / `innerHTML` 的渲染行为 / `addEventListener` / `remove`

所以面板 UI 一律用 `innerHTML` 拼字符串 + `querySelectorAll` 绑事件，不要写 `el.style.xxx = ...`，否则测试里过不去。

新写的纯函数要登记进 `main.js:1810` 的 `PURE` 表，测试通过 `P.<函数名>` 调用。

## 发布流程（重要）

Obsidian 社区市场是机器审核，卡这四条：

1. **Release 的 tag 必须等于 `manifest.json` 的 `version`**，而且要**没有 `v` 前缀**——写 `1.1.0`，不是 `v1.1.0`
2. Release 里必须挂 **`main.js`、`manifest.json`、`styles.css`** 三个散文件作为资产
3. `manifest.json` 的 `name` 必须是纯 ASCII
4. 命令 ID 不要带插件 ID 前缀（Obsidian 会自动加 `pulsewright:`）

分支：`main` 是已发布状态，`next` 是开发分支，发版时合并。

> 合并、打 tag、建 Release、挂三个散文件，这四步必须在同一次里做完。中途停下，仓库就是不一致的，审核会报「No release matches your manifest version」。

## 两端的差异

|  | Obsidian 端 | Zotero 端 |
|---|---|---|
| 形态 | `Plugin` 类 + `main.js` | bootstrapped extension |
| 入口 | `onload` / `onunload` | 文件作用域的 `startup` / `shutdown` / `onMainWindowLoad` |
| 界面 | `ItemView` + innerHTML | XUL `<panel>` popup |
| 分发 | 社区市场 | 手动装 `.xpi` |

Zotero 那侧的坑记在仓库 `zotero/README.md` 里：`bootstrap.js` 的函数必须挂在**文件作用域顶层**（挂对象上报 `missing bootstrap method`）；popup 必须挂 `#mainPopupSet` 才能显示；`openPopupAtScreen` 收的是**设备像素**；Gecko 不支持 `color-mix()`。
